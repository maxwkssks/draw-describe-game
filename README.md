# 그려봐! v4.0 / 4단계 — 팀전 라운드

이 폴더는 이전 v4.0 3단계 + 2인 저장 누락 수정본 위에 변경을 추가한 전체 프로젝트입니다.

## 지원 범위
- 개인전 랜덤/사진선택: 기존 흐름 유지 (서버 내부 구버전 RPC 호출).
- 팀전 랜덤/사진선택: 팀별 설명자 2명, 동일 사진, 원본 접근 제한, 그림 제출/타이머/종료 시 스냅샷.
- 팀전 사진 선택: **레드팀 설명자**가 원본 1개를 확정. 양 팀의 설명자에게만 원본 표시.
- 팀전 마감 뒤에는 `vote` 단계의 안내 화면에서 대기. **투표/점수/다음 라운드 기능은 아직 없습니다.**

## Supabase 변경 순서
1. 기존 운영 DB 백업.
2. 001/002/003이 적용된 DB에서 **`supabase/004_v4_team_rounds.sql`만 실행**.
3. 오류가 없으면 GitHub Desktop으로 프로젝트 파일을 덮어쓰고 Commit/Push. Vercel Production Ready 확인.
4. 참가자 4명(브라우저 서로 다른 세션)으로 테스트: 각 팀 2명, 전원 준비, 랜덤 1라운드 / 사진 선택 1라운드.
5. 두 설명자에게 같은 원본이 보이고 그림 참가자에겐 사진 경로가 반환되지 않는지 테스트.

## 주의
- 기존 스키마/001/002/003 SQL 다시 실행하지 말 것.
- 팀전 시작은 **팀 인원 2:2 이상, 최대 1명 차이**, 총 4~20명으로 제한.
- 팀전 설명을 듣는 디스코드 채널은 팀별로 별도 운영.
- 서버에서 `dd_v3_state/dd_v3_action`은 기존 개인전 호환성을 위해 내부 함수로 보존하며 외부 RPC 호출은 차단.
- `dd_round_drawings`에 각 라운드별 그림 저장. `vote` 단계 자동 진행은 아직 구현하지 않음.
- 운영 Supabase에 실제 실행한 통합 테스트는 이 패키지 제작 환경에서 수행하지 못함.
