# 그려봐! v5.1 — 방장 이탈 복구

기존 v5.0 무제한 모드 ZIP의 전체 웹사이트와 SQL을 보존하면서 방장 이탈 대처 기능만 추가했습니다.

## 설치 순서
1. 운영 Supabase 데이터베이스를 백업합니다.
2. Supabase SQL Editor에서 `supabase/008_v5_host_presence.sql` **하나만** 실행합니다. 기존 001~007을 재실행하지 마세요.
3. GitHub Desktop의 기존 `draw-describe-game` 저장소 폴더에 이 ZIP의 `draw-describe-web` **내부 파일과 폴더**를 덮어씁니다. `.env`나 secret 키는 올리지 않습니다.
4. GitHub Desktop에서 `v5.1 recover abandoned host`로 Commit, Push origin 합니다.
5. Vercel `Ready`를 확인하고, 서로 다른 브라우저 세션으로 테스트합니다.

## 작동
- 방장/참가자는 헤더 **방 나가기**를 누르거나 `Ctrl+Shift+E`로 나가기 확인 창을 엽니다. 이 단축키는 **자신이 방에서 나가는 동작**이지 모든 참가자를 강제로 종료시키는 동작이 아닙니다.
- 방장이 정상적으로 **방 나가기**를 누르면 기존 v5.0 서버 로직이 남은 참가자에게 즉시 권한을 이전합니다.
- 방장이 탭을 닫거나 접속을 잃어 나가기 요청이 도착하지 않으면, 남은 참가자의 heartbeat RPC가 **방장 최종 접속 45초 경과 후** 가장 먼저 들어온 접속 중 참가자를 새 방장으로 지정합니다. 브라우저 백그라운드 제한이나 네트워크 지연으로 이전까지 추가 시간이 걸릴 수 있습니다.
- 진행 중인 라운드를 방장 이탈로 이어갈 수 없다면 새 방장이 상단 **라운드 취소**를 눌러 대기실로 되돌립니다. 현재 라운드의 미확정 그림은 삭제하고 이전 라운드 점수는 유지합니다. 이는 방장 확인 창을 거치며 자동으로 취소되지 않습니다.
- 모든 참가자가 **방 나가기**를 정상적으로 눌러 방에 아무도 남지 않으면 기존 코드가 방을 바로 삭제합니다. 탭 강제 종료로 남은 유령 참가자 데이터는 자동으로 지워지지 않으며, 관리자 수동 청소 함수 `dd_v5_cleanup_inactive_rooms()`를 제공합니다. 6시간 이상 아무도 접속하지 않은 방만 대상으로 하며 필요 시 별도 정기 실행 설정이 필요합니다.

## 테스트 권장 시나리오
1. A가 방 생성, B가 코드로 입장, 준비 상태 확인.
2. A가 **방 나가기** 버튼 사용: B가 즉시 방장으로 표시되는지 확인.
3. 다른 방에서 A가 브라우저 탭을 강제 종료: B가 약 45초 후 방장이 되는지 확인.
4. 게임 진행 중 A가 나가 라운드가 막힘: 새 방장 B의 **라운드 취소** 버튼으로 대기실 복귀 확인.
5. A가 재접속 시 새 방장의 권한을 빼앗지 않는지 확인.
6. B까지 정상 퇴장 후 같은 방 코드 조회가 불가능한지 확인.

## 주의
SQL과 JS는 로컬 정적 테스트/빌드까지 검사했습니다. 실제 운영 Supabase 실행, 2인 접속, 자동 권한 이전은 별도 실서비스 테스트가 필요합니다. v5.0의 기존 블라인드 심사 미구현 상태는 이 변경에 포함되지 않습니다.
