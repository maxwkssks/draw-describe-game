# 그려봐! v4.0 — 팀전 자동 저장 / 마감 보완 (Step 4.1)

## 변경 내역
- 팀전 그림 제한시간 종료 시 브라우저 그림판 입력 잠금.
- 팀전 서버는 종료 시각부터 5초간 최종 `submitted=true` 그림 요청을 받아들임.
- 5초가 지난 후 서버가 `dd_round_drawings`에 당시 저장된 그림을 스냅샷하고 `vote` 단계로 전환.
- 방장의 조기 마감도 같은 5초 유예를 적용.
- 자동 저장 중 내용이 바뀌어도 새 내용이 다시 저장되도록 editVersion 기반 재저장 예약.
- 자동 저장 도중 제출 버튼을 눌렀을 때 제출 요청은 큐에 남겨 순서대로 처리.
- 최종 저장 실패 시 유예시간 이내 제한적인 재시도 및 실패 안내.
- 기존 개인전 RPC 및 게임 규칙은 그대로 둠. 팀전 그림 마감만 변경.

## 적용 순서
1. **운영 Supabase DB를 백업**하고 `supabase/005_v4_save_grace.sql`만 SQL Editor 새 쿼리에서 실행.
2. SQL 성공 후, 이 ZIP 안의 `public`, `scripts`, `tests`, `supabase` 등의 내용을 기존 GitHub Desktop 로컬 저장소 최상위로 덮어쓰기. `.git` 폴더는 유지.
3. GitHub Desktop에서 `v4.0 step 4.1 safe final save`로 커밋하고 `Push origin`.
4. Vercel Production 배포가 Ready인지 확인.
5. 서로 다른 4개 세션으로 팀전 테스트: 정상 마감 / 마감 직전 획 추가 / 자동 저장 중 최종 제출 / 조기 종료 / 일시적 통신 지연.

**기존 001~004 및 schema.sql을 다시 실행하지 마세요.**

## 검증 결과 및 한계
- Node 자동 테스트 25개 통과, JavaScript 구문 검사, 정적 Vercel 빌드 통과.
- 현재 환경에서 운영 Supabase에 005 SQL 적용, 4개 브라우저 실제 플레이, 네트워크 장애 테스트는 수행하지 못함.
- 5초 유예 시간을 초과한 요청은 서버에서 거절됨. 서버가 이미 받은 마지막 저장본은 보존하지만, 장시간 단절된 네트워크에서 마지막 획까지 반드시 보존할 수는 없음.
- 서버 마감은 누군가 상태 조회/RPC를 보낼 때 완료됨. 접속자가 아무도 없으면 실제 상태 변경은 다음 요청 때 발생할 수 있음.
- 클라이언트와 서버의 시계가 다른 경우 UI 잠금 시점과 서버 마감 시점에 차이가 날 수 있음. 이에 대한 보정은 추후 별도 작업.
