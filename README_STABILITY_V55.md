# 그려봐! v5.5 — 전체 게임 안정화 1단계

## 적용 범위
v5.4 대기실 동기화 배포본을 기준으로 `public/app.js`와 회귀 테스트를 수정했습니다. 개인전/팀전, 사진선택, 시간제/무제한, 그림 저장, 블라인드 평가, 설명자 관전, 방장 복구의 기존 기능을 유지합니다.

### 수정한 문제
1. **익명 인증 동시 요청:** 여러 API 요청에서 인증 상태를 동시에 확인하면 익명 로그인이 여러 번 시도될 수 있었습니다. 하나의 인증 Promise만 공유하고 실패하면 다음 호출에서 재시도합니다.
2. **응답이 오지 않는 방 상태 조회:** Supabase 상태 조회가 무기한 지연되면 `syncInFlight` 플래그가 해제되지 않아 후속 참가자 목록 갱신이 막혔습니다. UI 관점에서 10초 제한을 두고 재조회 가능하도록 변경했습니다.
3. **대기실 메타데이터/접속 확인 지연:** 메타데이터 조회와 접속 상태 확인에도 10초 제한을 적용해 다음 갱신이 계속 가능하게 했습니다.
4. **늦은 응답의 상태 덮어쓰기:** 상태 조회 요청 번호와 방/세션 식별자를 대조하여 오래된 요청의 응답이 새 방 상태를 덮어쓰지 못하게 했습니다.

### 설치
1. ZIP 내부 `draw-describe-web` 폴더 안의 파일과 폴더를 **기존 로컬 GitHub 저장소 루트**에 덮어씁니다 (`.git` 삭제 금지).
2. GitHub Desktop에서 변경 목록 확인 → Commit (`v5.5 stability polling and auth`) → Push origin.
3. Vercel 최신 배포가 Ready인지 확인합니다.
4. **신규 SQL은 없습니다.** 기존 v5.4까지의 운영 DB를 유지합니다.

### 로컬 검사
- Node.js 20 이상 설치 후 `npm test` 및 `npm run build`.
- 빌드에는 `SUPABASE_URL`, `SUPABASE_ANON_KEY`가 필요합니다. 실제 값은 Vercel 환경변수에만 저장하세요. 비밀키를 GitHub에 올리지 마세요.

### 남은 한계
- UI 타임아웃은 기존 네트워크 요청을 물리적으로 취소하지 않습니다. 느린 요청이 내부적으로 잠시 남을 수 있습니다.
- 운영 Supabase/RLS/Storage 정책과 20인 성능은 실제 서비스에 연결해 검증해야 합니다.
- 사용자가 브라우저를 종료하면 저장하지 못한 **마지막 획**은 지연/단절 상황에 따라 누락될 수 있습니다.
- 이번 패치는 DB RPC 함수와 실서비스를 직접 호출한 통합 테스트를 포함하지 않습니다.
