# 그려봐! Step 5 — 팀전 블라인드 심사·점수 공개

## 설치 순서 (중요)

1. 현재 운영 DB를 백업합니다. 작업 중인 방이 없는 시간에 수행하세요.
2. Supabase SQL Editor에서 기존 프로젝트의 **001, 002, 003, 004, 005, 007, 008** 적용 여부를 확인합니다. 아직 007/008을 적용하지 않았다면 이 업데이트를 바로 적용하지 마세요.
3. `supabase/009_v5_blind_team_scoring.sql` **한 파일만** New query에서 실행합니다. 성공 표시를 확인합니다.
4. 이 ZIP의 `draw-describe-web/` 폴더 *내부 파일*을 기존 GitHub Desktop 저장소 루트에 덮어씁니다. `.git` 디렉터리와 실제 `.env`를 건드리지 마세요.
5. `Commit to main` → `Push origin` → Vercel Production Ready 확인.
6. 기존 `SUPABASE_URL`, `SUPABASE_ANON_KEY`는 유지합니다.

**과거 실험용 `006_v4_blind_voting.sql`은 따로 실행하지 마세요.** 009에는 필요한 안전한 006 보조 함수가 포함되어 있고, 기존 007·008과 호환되도록 현재 상태/행동 함수를 감싸는 형태로 작성했습니다. 006을 나중에 실행하면 v5 기능을 덮어쓸 수 있습니다.

## 팀전 진행

- 4~20명, 2팀. 각 팀 1명씩 원본 사진 설명.
- 시간제는 그림 종료 후 5초 최종 저장 유예. 무제한은 각 팀 지정 완성 수 충족 시 종료.
- 작품마다 레드팀 최대 2명, 블루팀 최대 2명의 익명 심사자를 서버가 배정. 자신이 그린 작품은 본인에게 배정하지 않음.
- 원본은 심사 단계부터 모든 방 참가자에게 공개. 작품의 팀·작성자 정보는 결과 발표 전까진 반환하지 않음.
- 형태 40, 구도 30, 색상 20, 세부 10점. 심사 점수는 수정할 수 없음.
- 양 팀의 심사 평균을 50:50으로 합산. 어느 한 팀의 유효 심사가 없으면 그 작품은 미채점.
- 모든 배정표가 제출되거나 180초가 지나면 심사를 마감. 양 팀의 유효 작품이 있어야 해당 라운드를 누적 점수에 반영.
- 방장만 다음 라운드 / 최종 결과로 진행. 기존 방장 이탈 복구는 유지.

## 현재 제한·주의

- **운영 Supabase에서 실행 검증되지 않았습니다.** 51개 로컬 정적·회귀 테스트, JS 문법 검사 및 빌드만 통과했습니다.
- 별도 심사위원이 없는 참여자 평가인 만큼 팀 담합 가능성을 완전히 없앨 수 없습니다.
- 종료 180초 판정은 현재 상태 조회 요청이 있어야 진행됩니다. 모든 사람이 동시에 접속을 닫는 경우 늦어질 수 있습니다.
- 초기 v4 SQL 001에 정의된 `dd_v4_submit_vote`와 `dd_v4_my_ballot` 함수에 의존합니다.
- 무제한 팀전에서 제출이 적으면 해당 라운드에 보존된 작품만 평가합니다.
- 기존 팀전 게임방이 진행 중이라면 완료한 뒤 SQL을 적용하세요.

## 개발자 테스트

```
npm test
SUPABASE_URL=https://example.supabase.co SUPABASE_ANON_KEY=sb_publishable_test npm run build
```

이 명령은 실제 Supabase에 연결하는 테스트가 아닙니다. 실제로는 일반 브라우저/시크릿 창 및 서로 다른 기기에서 4명(2:2)의 독립 익명 세션으로 한 라운드를 진행하여 심사·결과·재시작을 검증해야 합니다.
