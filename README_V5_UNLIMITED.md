# 그려봐! v5.0 무제한 모드 (라운드별 완성 수)

## 기존 프로젝트 위에 업데이트
- **기준:** v4 Step 4.1 최종 저장 수정본. 이 배포에는 006 블라인드 투표 UI는 포함하지 않습니다.
- 기존 개인전/팀전, 4가지 사진 모드 조합, 사진 카테고리, 관리자 기능, 시간제 2·3·5분은 유지합니다.
- 신규 모드: **무제한(시간 없음)**. 방장은 한 라운드 완성 수를 설정할 수 있습니다.
- 개인전: 그림 담당자들 중 `completion_target`명이 완성 버튼을 누르면 익명 1~3등 심사로 이동.
- 팀전: 레드와 블루 각각 `completion_target`명 이상 완료 시 `vote` 단계로 이동. 같은 수의 먼저 제출한 그림만 심사 대상이 됩니다.
- 방장은 조기 마감을 요청할 수 있습니다. 미완성 작품은 심사 대상에서 제외합니다.
- 한 참가자는 한 라운드에 한 번만 최종 제출할 수 있습니다. 타이머가 없는 대신 제출 즉시 편집 잠금.

## 적용 순서 (반드시 SQL 먼저)
1. 기존 Supabase DB 백업. 가능하면 테스트 프로젝트에서 SQL부터 검증.
2. 이 ZIP의 `supabase/007_v5_unlimited_mode.sql`을 기존 SQL Editor에서 **한 번** 실행합니다. 기존 schema.sql이나 001~005는 재실행하지 않습니다. 005가 설치되어 있어야 합니다.
3. GitHub Desktop → 기존 `draw-describe-game` 저장소 → Show in Explorer.
4. ZIP의 `draw-describe-web` 폴더 안의 파일을 저장소 루트에 복사/덮어쓰기. `.git` 삭제 금지, `.env`/비밀키 업로드 금지.
5. GitHub Desktop에서 `v5.0 unlimited per-round completion`으로 Commit → Push origin.
6. Vercel의 최신 배포가 Ready인지 확인한 다음 Ctrl+Shift+R로 새로고침.
7. 새로 만든 방에서만 신규 설정 적용 확인. 진행 중인 방은 모드 변경 불가.

## 권한 및 공정성
- 무제한 방 생성/설정은 방장이 지정하며, 서버는 실제 입장 인원 기준으로 시작 가능 여부를 다시 검사합니다.
- 완료 목표는 인원 2~20명에서 **실제 그리는 사람 수**로 제한: 개인전 정원-1, 팀전 정원 절반(내림)-1 이하.
- 20명 방에 2명만 들어온 상태로 목표 9명을 요구하는 오류를 서버에서 차단합니다.
- 팀전은 동시 제출을 방 단위의 `FOR UPDATE` 잠금으로 직렬화하며 완성 시 즉시 단계를 전환합니다.
- 팀전 조기 종료 시 그림 수가 부족해 양 팀의 점수 비교가 성립하지 않을 수 있습니다. 이 경우 경기는 유효 승리로 취급하지 않는 것이 안전합니다.
- 무제한에 맞춰 완료한 작품만 팀전 라운드별 테이블에 저장합니다. 순위는 설명자/블라인드 평가 로직에서 처리합니다.

## 제한 / 배포 전 확인할 점
- **팀전 블라인드 평가 UI가 아직 기존 프로젝트에 없으면** 작품은 안전하게 저장되지만 `vote` 단계에서 대기합니다. 기존 v4 Step 5(006) 투표 구현과 운영 검증이 필요합니다.
- 이 파일은 **로컬 코드 검사 및 정적 웹 빌드**를 통과하도록 준비했으며 Supabase 운영 DB SQL 실행 및 4~20명 접속 테스트를 수행하지 않았습니다.
- 기존 `dd_v4_action`, `dd_v4_state` 함수가 없고 `dd_action`, `dd_state`로만 배포된 v4 Step 4.1을 전제로 합니다. 006이 이미 실행되어 있다면 SQL 스냅샷/권한과의 호환성을 테스트 프로젝트에서 먼저 확인하세요.
- 활성 사진이 없어도 방 만들기만 가능하고 시작 시 서버에서 사진 유효성을 검사합니다.
- 20명 동시 네트워크 지연과 접속 이탈, 방장 강제 마감 시나리오는 별도 실전 검증이 필요합니다.
